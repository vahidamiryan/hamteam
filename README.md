# هم‌تیم (HamTeam)

اپلیکیشن سادهٔ مدیریت تسک و همکاری تیمی: برد کشیدنی، گفت‌وگوی تیمی روی هر تسک، اعضای تیم با آواتار مجزا، هدف‌گذاری بلندمدت و سررسید شمسی.

کاملاً **دوزبانه**: فارسی راست‌به‌چپ با تقویم جلالی و ارقام فارسی، و انگلیسی چپ‌به‌راست با تقویم میلادی — با یک کلیک جابه‌جا می‌شود. آمادهٔ استقرار روی Vercel (و هر پلتفرم Node دیگر).

---

## امکانات

- **برد کارها** با پنج ستون: بک‌لاگ، در حال انجام، در انتظار، مسدود، انجام‌شده. جابه‌جایی کارت‌ها با کشیدن و رها کردن (Drag & Drop) و افزودن سریع تسک در هر ستون.
- **تسک‌ها**: عنوان، توضیحات، مسئول، وضعیت، اولویت، سررسید (تقویم شمسی)، دلیل مسدودی، اتصال به هدف.
- **همفکری تیمی**: گفت‌وگوی هر تسک با نویسنده، آواتار و زمان نسبی («چند دقیقه پیش»). نوشتن با `Ctrl/⌘ + Enter`.
- **منشن هم‌تیمی**: تایپ `@` در گفت‌وگو فهرست اعضا را باز می‌کند (با `↑`/`↓` و `Enter`)؛ منشن‌ها در متن برجسته می‌شوند و منشنِ خودِ شما رنگ «در انتظار» می‌گیرد.
- **پیوست تصویر**: چسباندن از کلیپ‌بورد، انتخاب فایل یا کشیدن روی کادر گفت‌وگو. تصویر در مرورگر فشرده (WebP/JPEG، حداکثر ۱۰۰۰px) و به‌صورت Data URL در همان سند ذخیره می‌شود؛ حداکثر ۶ تصویر برای هر پیام.
- **پیگیری تغییرات**: هر تسک که بعد از آخرین بازدید شما تغییر کرده یا در آن منشن شده‌اید یک نقطهٔ آرام روی کارت/ردیف می‌گیرد؛ از منوی فیلتر می‌توانید «تغییرات جدید» یا «منشن‌های من» را جدا ببینید و همه را دیده‌شده کنید.
- **دوزبانگی کامل (فارسی/انگلیسی)**: تغییر زبان از هدر، تغییر خودکار `dir`/`lang` سند، تقویم شمسی برای فارسی و میلادی برای انگلیسی، ارقام فارسی، و ماندگاری انتخاب زبان در مرورگر.
- **آواتار تصادفی**: ۱۲ آواتار SVG محلی؛ هر عضو هنگام ساخت یک آواتار تصادفی می‌گیرد (پایدار و قابل تغییر در فرم ویرایش).
- **افراد**: کارت هر عضو با نقش، ایمیل، آواتار رنگی اختصاصی و آمار (باز / در حال انجام / مسدود / عقب‌افتاده)؛ انتخاب «من کدام عضو هستم»، فیلتر برد بر اساس عضو، ویرایش و حذف عضو.
- **اهداف**: هدف‌های بلندمدت با تاریخ هدف، مالک و **پیشرفت خودکار** بر اساس تسک‌های وصل‌شده.
- **جست‌وجو و فیلتر** روی عنوان/توضیح/دلیل مسدودی و فیلتر بر اساس مسئول.
- **آمار کلی**: کل تسک‌ها، در حال انجام، مسدود، سررسید گذشته، بدون مسئول.
- دادهٔ نمونهٔ فارسی از ابتدا آماده است و با دکمهٔ «بازنشانی» به حالت اولیه برمی‌گردد.

## اجرای محلی

```bash
npm install
npm run dev          # http://localhost:3000
```

بدون هیچ تنظیم دیگری اجرا می‌شود و داده‌ها در `.data/workspace.json` ذخیره می‌شوند.

```bash
npm run build && npm start   # اجرای نسخهٔ تولید
npm run lint                 # ESLint
```

## ذخیره‌سازی: سه حالت

کل فضای کاری (اعضا، تسک‌ها، کامنت‌ها، هدف‌ها) یک سند JSON با شمارندهٔ نسخه است. نوشتن‌ها سریالی و با بررسی نسخه انجام می‌شوند تا دو درخواست هم‌زمان داده را خراب نکنند.

| حالت | چه زمانی | پایداری |
| --- | --- | --- |
| `postgres` | `DATABASE_URL` تنظیم شده باشد | پایدار — مناسب تولید |
| `file` | اجرای محلی یا سرور خودتان (بدون `DATABASE_URL`) | پایدار در `.data/workspace.json` |
| `ephemeral` | روی Vercel بدون `DATABASE_URL` | موقت در `/tmp`؛ با هر ری‌استارت بازنشانی می‌شود |

حالت فعال در نوار بالای برنامه نمایش داده می‌شود و در حالت موقت یک هشدار زرد ظاهر می‌شود. برای دیدن وضعیت:

```bash
curl http://localhost:3000/api/workspace | jq '.storage'
```

### اتصال یک Postgres رایگان (توصیه‌شده برای Vercel)

هر سرویس Postgres رایگان کار می‌کند؛ مثلاً **Neon** یا **Supabase**:

1. در [neon.com](https://neon.com) یا [supabase.com](https://supabase.com) پروژهٔ رایگان بسازید.
2. رشتهٔ اتصال (`Connection string`) را کپی کنید؛ باید شامل `?sslmode=require` باشد.
3. آن را به‌عنوان `DATABASE_URL` تنظیم کنید (محلی در `.env.local`، روی Vercel در Environment Variables).
4. برنامه را ری‌استارت کنید. جدول `workspace_doc` در اولین درخواست خودکار ساخته و با دادهٔ نمونه پر می‌شود.

`.env.local`:

```bash
DATABASE_URL="postgresql://user:password@host/dbname?sslmode=require"
```

## استقرار روی Vercel

1. مخزن را در GitHub قرار دهید.
2. در [vercel.com/new](https://vercel.com/new) مخزن را Import کنید. تنظیمات پیش‌فرض Next.js درست است (Build: `next build`).
3. در بخش **Environment Variables** مقدار `DATABASE_URL` را اضافه کنید.
   - بدون این متغیر هم سایت بالا می‌آید، اما داده‌ها موقتی‌اند (حالت نمایشی).
4. Deploy.

هیچ متغیر محیطی دیگری لازم نیست. برای دامنهٔ اختصاصی، در تنظیمات پروژهٔ Vercel دامنه را اضافه کنید.

> برنامه روی هر میزبان Node (Docker، Railway، Fly.io، سرور شخصی) هم اجرا می‌شود؛ فقط کافی است `PORT` را تنظیم کنید و برای پایداری `DATABASE_URL` بدهید.

## API

همهٔ پاسخ‌ها JSON و به شکل `{ data, storage }` یا `{ error }` هستند. خطاهای اعتبارسنجی با کد `400` و پیام فارسی برمی‌گردند.

| متد | مسیر | کار |
| --- | --- | --- |
| `GET` | `/api/workspace` | خواندن کل فضای کاری + وضعیت ذخیره‌سازی |
| `POST` | `/api/workspace/reset` | بازنشانی به دادهٔ نمونه |
| `POST` | `/api/tasks` | ساخت تسک |
| `PATCH` `DELETE` | `/api/tasks/:id` | ویرایش / حذف تسک (کامنت‌هایش هم حذف می‌شوند) |
| `POST` | `/api/tasks/:id/comments` | افزودن کامنت |
| `DELETE` | `/api/comments/:id` | حذف کامنت |
| `POST` | `/api/members` | افزودن عضو |
| `PATCH` `DELETE` | `/api/members/:id` | ویرایش / حذف عضو (تسک‌هایش بدون مسئول می‌شوند) |
| `POST` | `/api/goals` | ساخت هدف |
| `PATCH` `DELETE` | `/api/goals/:id` | ویرایش / حذف هدف |

نمونه:

```bash
# ساخت تسک
curl -X POST http://localhost:3000/api/tasks \
  -H "content-type: application/json" \
  -d '{"title":"آماده‌سازی گزارش هفتگی","status":"in_progress","priority":"high",
       "assigneeId":"mem_sara","dueDate":"2026-12-01"}'

# تغییر وضعیت
curl -X PATCH http://localhost:3000/api/tasks/<id> \
  -H "content-type: application/json" -d '{"status":"blocked","blockedReason":"منتظر دسترسی"}'
```

## معماری

- **دامنه، جدا از رابط کاربری**: `src/lib/domain` هیچ import‌ای از React ندارد. `WorkspaceIndex` یک سند خام را به ساختار قابل جست‌وجو تبدیل می‌کند (نقشهٔ اعضا/هدف‌ها/تسک‌ها، گفت‌وگوهای هر تسک و آمار هر عضو) و برای هر نسخهٔ سند یک‌بار ساخته می‌شود؛ `TaskQuery` فیلترها را به شرط‌های مستقل می‌شکند؛ `workspace-patches` به‌روزرسانی تغییرناپذیر را با اشتراک ساختاری انجام می‌دهد تا فقط کارتِ تغییرکرده رندر شود.
- **مخزن به‌جای state پراکنده**: `WorkspaceStore` تنها منبع حقیقت سمت کلاینت است؛ با الگوی Observer به `useSyncExternalStore` وصل می‌شود و API دامنه‌محور (ساخت تسک، ثبت پیام، دیدن تسک…) می‌دهد. وابستگی‌هایش تزریق می‌شوند: کلاینت HTTP، لینک همگام‌سازی زنده، مخزن هویت و مقصد رویدادها. `workspace-provider.tsx` فقط آداپتور است: اسنپ‌شات را به context تبدیل می‌کند و رویدادها را با زبان جاری به توست ترجمه می‌کند.
- **کش‌های کوچک و مشخص**: الگوی منشن برای هر آرایهٔ اعضا یک‌بار ساخته می‌شود، `Intl.DateTimeFormat` برای هر ترکیب زبان/گزینه کش می‌شود و جست‌وجو از متن نرمال‌شدهٔ ایندکس استفاده می‌کند.
- **جست‌وجوی روان**: ورودی جست‌وجو همان state فیلتر است (بدون state موازی و تایمر) و فهرست با `useDeferredValue` دیرتر رندر می‌شود؛ با ۳۰۰ تسک هیچ long task ثبت نشد.

## دوزبانگی

- متن هر موجودیت در **دو فیلد** نگه داشته می‌شود: فیلد پایه فارسی (`title`، `description`، …) و فیلد انگلیسی اختیاری (`titleEn`، `descriptionEn`، …). اگر ترجمهٔ انگلیسی خالی باشد، همان متن فارسی نمایش داده می‌شود.
- رشته‌های رابط کاربری در `src/lib/i18n.ts` به شکل جفت `[فارسی, English]` هستند. برای افزودن رشتهٔ تازه، یک کلید به همان شیء اضافه کنید؛ TypeScript کلیدهای نامعتبر را در `t(...)` رد می‌کند.
- زبان در `localStorage` (`hamteam:locale`) ذخیره می‌شود؛ اسکریپت کوچکی در `layout.tsx` مقدار `lang`/`dir` را پیش از رنگ‌آمیزی صفحه ست می‌کند تا پرش نداشته باشیم.
- تاریخ‌ها همچنان به شکل `YYYY-MM-DD` ذخیره می‌شوند؛ فقط نمایش و ورودشان زبان‌آگاه است (`src/lib/dates.ts`).

## یادداشت‌های طراحی

- **تاریخ‌ها** در سراسر برنامه به شکل `YYYY-MM-DD` ذخیره می‌شوند (بدون ساعت) تا مسئلهٔ منطقهٔ زمانی پیش نیاید؛ نمایش در فارسی جلالی و در انگلیسی میلادی است.
- **به‌روزرسانی خوش‌بینانه**: رابط کاربری بلافاصله تغییر را نشان می‌دهد و پاسخ سرور آن را تأیید یا اصلاح می‌کند.
- **فونت** وزیرمتن به‌صورت محلی در `public/fonts` سرو می‌شود؛ نیازی به CDN یا اینترنت در زمان اجرا نیست.
- **جهت بصری**: رمپ خنثی گرم («کاغذ») با یک لهجهٔ آبیِ مرکبی که فقط در دکمهٔ اصلی، وضعیت انتخاب‌شده و تمرکز به کار می‌رود. وضعیت‌ها رنگ معنایی دارند (`--status-*`) و بقیهٔ متادیتا متن آرام است تا هر کارت یک نقطهٔ رنگیِ روشن داشته باشد.
- **امضای کارت**: مُهر تاریخ جلالی/میلادی در پای کارت (`DueStamp`) به‌جای نشان‌های پرتعداد؛ فقط سررسید گذشته و امروز رنگ می‌گیرند.
- **منشن و پیوست در همان سند**: پیام‌ها فقط `body`/`bodyEn` و یک آرایهٔ `attachments` دارند؛ تصویر به‌جای فضای ذخیره‌سازی بیرونی، Data URL فشرده است (سقف حجم در `validation.ts` و `image-utils.ts` مشترک است) تا هم‌گام‌سازی و بکاپ یک‌جا انجام شود.
- **«دیده‌نشده» بدون سرور**: هر کاربر یک سند کوچک در `localStorage` دارد (`hamteam:seen:<memberId>`) با `baseline` و زمان مشاهدهٔ هر تسک؛ همین سند تصمیم می‌گیرد چه چیزی «تغییر جدید» است. چون از `useSyncExternalStore` خوانده می‌شود، نه hydration به‌هم می‌ریزد و نه `setState` داخل effect لازم است.
- **بدون احراز هویت**: «من کدام عضو هستم» در `localStorage` نگه داشته می‌شود. برای استفادهٔ واقعی، یک لایهٔ ورود (مثلاً Auth.js) اضافه کنید و `authorId` را از نشست بگیرید.
